    Installation Guide

    Prerequisites

    Before you begin, ensure you have the following installed:

    • Python 3.8 or higher
    • Tesseract OCR
    • CUDA (for GPU acceleration, optional)
    • Git

    Installing Tesseract OCR

    macOS

    brew install tesseract

    Ubuntu/Debian

    sudo apt-get install tesseract-ocr

    Windows

    Download and install from Tesseract OCR GitHub

    Project Setup

    1. Clone the repository: 

      git clone https://github.com/Wisammad/InovoiceScanner.git
cd InovoiceScanner

    2. Create and activate a virtual environment: 

      python -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate

    3. Install dependencies: 

      pip install -r requirements.txt

    4. Set up the project structure: 

      # Create necessary directories
mkdir -p data/raw/{Invoices,PurchaseOrders,Monthly,MonthlyCategory,Shipping orders}
mkdir -p data/processed/{images,text,metadata}
mkdir -p data/models/{classification,extraction}
mkdir -p src/uploaded_files
mkdir -p src/processed_files

    Running the System

    1. Start the Main Application

    # Start the main processing pipeline
python src/main.py

    This will: - Initialize all components - Start the document processor - Begin monitoring for new documents

    2. Start the API Server

    # Start the API server (in a new terminal)
python src/api.py

    The API server will be available at: - URL: http://127.0.0.1:5002 - Swagger Documentation: http://127.0.0.1:5002/docs

    3. Process Documents

    You can process documents in several ways:

    a. Using the API: 

    # Upload a single document
curl -X POST -F "file=@path/to/document.pdf" http://127.0.0.1:5002/api/upload

# Process a document
curl -X POST -H "Content-Type: application/json" \
     -d '{"document_id": "123"}' \
     http://127.0.0.1:5002/api/process

    b. Using the batch processing script: 

    python src/main.py --mode batch_process \
                   --input-dir data/raw \
                   --output-dir data/processed

    c. Using the training pipeline: 

    # Train the classification model
python src/classification/train_classifier.py \
       --data-dir data/processed \
       --output-dir data/models/classification

# Train the extraction model
python src/extraction/train_extractor.py \
       --data-dir data/processed \
       --output-dir data/models/extraction

    4. Monitor the System

    # View real-time logs
tail -f src/invoice_scanner.log

# Check processing status
curl http://127.0.0.1:5002/api/documents

# View system status
curl http://127.0.0.1:5002/api/debug

    Verification Steps

    After installation, verify the setup:

    1. Check Component Status: 

      python src/main.py --check-status

    2. Run Test Document: 

      # Process a sample document
python src/main.py --test-document path/to/sample.pdf

    3. Verify API Connection: 

      curl http://127.0.0.1:5002/api/debug

    4. Check Model Status: 

      python src/classification/train_classifier.py --verify-models

    Environment Variables

    Create a .env file in the root directory: 

    # Create and edit .env file
cat > .env << EOL
TESSERACT_PATH=/usr/local/bin/tesseract
MODEL_PATH=src/classification/classifier_models
DATA_PATH=data
API_PORT=5002
DEBUG_MODE=True
EOL

    Common Commands

    Here are some commonly used commands:

    # Start everything (main app and API)
./start.sh

# Process a single document
python main.py --process path/to/document.pdf

# Batch process documents
python main.py --batch-process input_folder/

# Retrain models
python main.py --retrain

# Clear processed files
python main.py --clean-processed

# Run diagnostics
python main.py --diagnose

    Document Categories

    The system is designed to classify documents into the following categories:

    Invoices (Required)

    • Commercial documents with itemized products/services

    • Contains payment terms and due dates

    • Includes invoice numbers and amounts

    PurchaseOrders - Authorization documents for purchases

    • Contains PO numbers and vendor details

    • Includes item descriptions and quantities

    Monthly (Stock Reports) - Monthly inventory summaries

    • Contains stock quantities and values

    • Includes month-over-month comparisons

    MonthlyCategory (Categorized Stock Reports) - Category-specific inventory reports

    • Contains detailed product line information

    • Includes subcategory identifiers

    Shipping orders - Documents for goods shipment

    • Contains shipping addresses and tracking

    • Includes product quantities for delivery

    Preparing Training Data

    • Create the necessary directories:
    mkdir -p data/raw/{invoices,purchase_orders,monthly,monthly_category,shipping_orders}
mkdir -p data/processed/{images,text,metadata}
mkdir -p data/models/{classification,extraction}

    Add your training documents: - Place PDF documents in their respective category folders under data/raw/

    • Ensure each category has sufficient samples (minimum 50 documents recommended)

    • Documents should be representative of real-world variations

    API Usage

    Uploading Documents

    • Single Document: 

      curl -X POST -F "file=@path/to/document.pdf" http://127.0.0.1:5002/api/upload

    • Batch Upload: 

      curl -X POST -F "files=@path/to/documents.zip" http://127.0.0.1:5002/api/batch-upload

    Processing Documents

    • Process Single Document: 

      curl -X POST -H "Content-Type: application/json" \
     -d '{"document_id": "123"}' \
     http://127.0.0.1:5002/api/process

    • Get Results: 

      curl http://127.0.0.1:5002/api/results/123

    API Endpoints

    All API endpoints are available at http://127.0.0.1:5002:

    • /api/upload - Upload documents
    • /api/process/<file_id> - Process documents
    • /api/documents - List all documents
    • /api/search - Search documents
    • /api/extractor - Manage extractor configuration

    Data Management

    Adding New Training Data

    Prepare your documents:

    • Ensure documents are in PDF format
    • Organize by document type
    • Remove sensitive information
    • Follow category-specific requirements

    Upload to the system:

    • Place in appropriate data/raw/ subdirectory
    • Or use the batch upload API

    Update training: - Run preprocessing - Retrain models - Validate results

    Data Backup

    Regularly backup your data: 

    tar -czf data_backup.tar.gz data/

    Troubleshooting

    Common Issues

    OCR Errors - Ensure Tesseract is properly installed - Check image quality - Verify language support

    Model Training Failures - Check GPU memory (if using) - Verify data format - Ensure sufficient training samples per category

    API Connection Issues - Check server status - Verify port availability - Check firewall settings

    Logs

    Check logs for detailed error information: 

    tail -f src/invoice_scanner.log

    Next Steps

    After installation:

    • Test the system with sample documents from each category
    • Monitor model performance for each document type
    • Fine-tune models as needed
    • Scale the system based on usage

    Document Quality Challenges

    Our system is trained to handle various document quality issues:

    Bad Quality Scenarios

    Too Dark Documents

    • Documents with poor contrast

    • Scanned copies with dark backgrounds

    • Faded text on dark paper

    • Solution: Advanced image preprocessing with contrast enhancement

    • Layout Issues

    • Amounts overshadowed by complex layouts

    • Text overlapping with background elements

    • Irregular formatting and positioning

    • Solution: Layout analysis and text isolation algorithms

    • Feeble or Out of Bounds

    • Faint or barely visible text

    • Content extending beyond standard margins

    • Skewed or rotated content

    • Solution: Image enhancement and geometric correction

    Extraction Confidence

    For each extracted field, the system provides:

    • Confidence score (0-1)
    • Quality indicators
    • Extraction method used
    • Alternative values if uncertain

    Example response: 

    {
    "invoice_number": {
        "value": "INV-2024-123",
        "confidence": 0.92,
        "quality_issues": ["slight_fade"],
        "method": "enhanced_ocr"
    },
    "total_amount": {
        "value": "1234.56",
        "confidence": 0.85,
        "quality_issues": ["overshadowed"],
        "method": "layout_analysis"
    }
}

    Quality-Based Processing

    The system adapts its processing based on document quality:

    1. High Quality Documents (Quality Score > 0.8)
    2. Standard OCR processing
    3. Direct text extraction

    4. Regular confidence thresholds

    5. Medium Quality Documents (Quality Score 0.5-0.8)

    6. Enhanced preprocessing
    7. Multiple OCR passes
    8. Layout analysis

    9. Cross-validation of results

    10. Low Quality Documents (Quality Score < 0.5)

    11. Intensive preprocessing
    12. Advanced enhancement techniques
    13. Multiple extraction methods
    14. Human verification flags

    Configuration Options

    You can configure quality thresholds:

    quality_config = {
    'min_brightness': 0.3,
    'min_contrast': 0.4,
    'max_noise': 0.6,
    'min_text_clarity': 0.5
}

    Handling Mixed Quality Batches

    When processing multiple documents:

    python src/main.py --mode batch_process \
                   --input-dir data/raw \
                   --quality-threshold 0.4 \
                   --enhancement-level auto

    This will: - Automatically assess document quality - Apply appropriate preprocessing - Group documents by quality level - Adjust extraction parameters - Generate quality reports
